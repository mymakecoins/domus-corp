# V1-601 MCP Catalog & Manifest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the JSON Schema for MCP manifests in `contracts` and implement the MCP server catalog administration routes in `apps/control-plane` (TypeScript/Fastify), ensuring all registered MCP servers start in a disabled state (`enabled: false`) pending formal security approval.

**Architecture:** 
1. Define `mcp-manifest.schema.json` in `contracts/json-schema/v1/` specifying server identity, owner, endpoint, tool definitions, risk levels (`low`, `medium`, `high`, `irreversible`), allowed workspaces, and initial disabled status.
2. Implement MCP domain entities and service layer in `apps/control-plane/src/domain/mcp` and `src/application/mcp`.
3. Register Fastify HTTP routes under `/v1/admin/mcp/servers` in `apps/control-plane/src/interfaces/http/mcp/routes.ts` with strict security authorization, idempotency, and fail-closed defaults.

**Tech Stack:** TypeScript, Node.js, Fastify, JSON Schema (Draft 2020-12), Vitest / Node test runner.

## Global Constraints

- **Strict Fail-Closed Defaults:** Every newly registered MCP server MUST be initialized with `enabled: false` and `status: "PENDING_SECURITY_APPROVAL"`.
- **Egress Boundary:** No external HTTP calls are made during catalog registration.
- **Contract Schema:** Must adhere strictly to JSON Schema Draft 2020-12 envelope standards in `contracts/json-schema/v1/common.schema.json`.

        },

- [ ] **Step 1: Write domain models for MCP Catalog**

Create `apps/control-plane/src/domain/mcp/mcp-catalog.ts`:
```typescript
export type McpRiskLevel = "low" | "medium" | "high" | "irreversible";
export type McpServerStatus = "PENDING_SECURITY_APPROVAL" | "APPROVED" | "REVOKED";

export type McpToolDefinition = Readonly<{
  toolId: string;
  name: string;
  description: string;
  riskLevel: McpRiskLevel;
  parametersSchema: Record<string, unknown>;
}>;

export type McpServerEntry = Readonly<{
  serverId: string;
  tenantId: string;
  name: string;
  description: string;
  ownerUserId: string;
  endpointUrl: string;
  tools: readonly McpToolDefinition[];
  enabled: boolean;
  status: McpServerStatus;
  allowedWorkspaces: readonly string[];
  createdAt: string;
  updatedAt: string;
}>;
```

- [ ] **Step 2: Write unit test for MCP Catalog Application Service**

Create test file verifying that new registrations are ALWAYS initialized with `enabled: false` and `status: "PENDING_SECURITY_APPROVAL"`.

- [ ] **Step 3: Implement `ManageMcpCatalogService`**

Implement in-memory / persistent catalog service with methods:
- `registerServer(input)` -> returns `McpServerEntry` with `enabled: false` and `status: "PENDING_SECURITY_APPROVAL"`
- `listServers(tenantId, workspaceId)` -> returns filtered `McpServerEntry[]`
- `getServer(serverId)` -> returns `McpServerEntry`
- `approveServer(serverId, securityActor)` -> transitions to `APPROVED` and `enabled: true`
- `revokeServer(serverId, securityActor, reason)` -> transitions to `REVOKED` and `enabled: false`
