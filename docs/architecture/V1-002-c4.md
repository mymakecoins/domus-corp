# V1-002 — Arquitetura C4 e fluxos críticos

**Status:** Aprovado  
**Data:** 07/08/2026  
**Aprovador:** Marcos Wasem  
**Escopo:** C4 níveis 1 e 2, fronteiras de confiança e fluxos de pergunta, ingestão e ação

Este documento torna renderizável a arquitetura proposta pelo ADR-001. Os diagramas usam Mermaid e preservam a separação entre os planos Harness, Knowledge, Intelligence e Action. O Quality Loop é uma capacidade transversal, não um quinto ponto de autoridade.

## 1. Invariantes

1. O Model Gateway TypeScript é o único egress para LLMs, embeddings hospedados e APIs de providers.
2. MCPs e escrita externa só são alcançados pelo Tooling/MCP e pelo Action Gateway TypeScript.
3. Serviços Python recebem identidade e `EffectivePolicy` versionadas, podem reduzir o escopo e nunca ampliá-lo.
4. PostgreSQL é a fonte transacional; MinIO e Qdrant armazenam derivados/originais sujeitos à autoridade e ao ciclo de vida registrados no PostgreSQL.
5. Falha de identidade, policy, ACL, classificação, budget, auditoria ou aprovação bloqueia a operação.
6. Memória pessoal local não é conhecimento corporativo até passar por publicação, classificação, owner e aprovação.

## 4. Fluxo de pergunta fundamentada

```mermaid
sequenceDiagram
  actor U as Usuário
  participant C as Cliente
  participant H as Harness TS
  participant R as Retrieval Python
  participant I as Intelligence Python
  participant G as Model Gateway TS
  participant P as Provider

  U->>C: pergunta
  C->>H: request + sessão + workspace
  H->>H: identidade, policy, classificação e budget
  alt admissão negada ou dependência indisponível
    H-->>C: bloqueio tipado e auditado
  else admitida
    H->>R: escopo mínimo + policy_version
    R->>R: ACL antes da busca + vigência
    R-->>I: evidências citáveis
    I->>G: prompt separado de dados + evidências
    G->>G: revalidar policy, redaction e reserva
    G->>P: egress permitido
    P-->>G: resposta
    G-->>I: saída + uso
    I-->>H: fatos, inferências, estado e citações
    H-->>C: stream tipado
  end
```

## 5. Fluxo de ingestão

```mermaid
sequenceDiagram
  actor O as Owner/Administrador
  participant S as Source Registry TS
  participant W as Worker Python
  participant F as Fonte
  participant D as Dados internos
  participant G as Model Gateway TS

  O->>S: selecionar fonte e confirmar escopo
  S->>S: validar owner, classificação, SLA e policy
  S->>W: job + cursor + escopo imutável
  W->>F: buscar somente itens autorizados
  W->>W: scan, parsing, dedupe e prompt-injection checks
  alt conteúdo suspeito ou inválido
    W->>D: quarentena + metadados auditáveis
  else elegível
    opt classificação/embedding hospedado
      W->>G: chamada governada
      G-->>W: resultado autorizado
    end
    W->>D: original versionado + metadados + índice derivado
    W-->>S: estado e cursor
  end
```

## 6. Fluxo de ação

```mermaid
sequenceDiagram
  actor U as Usuário
  participant I as Intelligence
  participant A as Action Gateway TS
  participant UI as Action Review
  participant M as MCP Proxy TS
  participant X as Sistema externo

  I->>A: proposta, nunca execução
  A->>A: policy, alçada, risco, budget e parâmetros
  A-->>UI: preview redigido + impacto
  UI->>U: solicitar confirmação/aprovação
  U->>UI: decisão explícita
  UI->>A: confirmação vinculada à versão/hash
  A->>A: reautorizar + reservar idempotency key
  alt negada, expirada ou alterada
    A-->>UI: bloqueio sem execução
  else aprovada
    A->>M: ferramenta allowlisted + credencial escopada
    M->>X: chamada externa
    X-->>M: resultado
    M-->>A: resultado redigido
    A-->>UI: recibo terminal auditável
  end
```

## 7. Encaminhamentos

- A ingestão acessará fontes por connector isolado dentro de TB-3, limitado a fontes registradas e sem acesso a provider, MCP ou destino de ação. Uma mudança para proxy dedicado TypeScript exigirá análise arquitetural, mas não altera essa restrição.
- Definir, na V1-003, os schemas e protocolos das setas cross-runtime.
- Materializar allowlists, identidades de workload e políticas de rede na V1-006.
